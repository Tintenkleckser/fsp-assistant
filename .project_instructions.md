# FSP-Assistent Project Instructions

## Overview
A Next.js app for **Fachsprachenprüfung (FSP)** preparation — German medical language exam for foreign doctors. Focus on the **3 Prüfungsteile**: Anamnese (Arzt-Patient), Dokumentation (Kurz + Ausführlich), and Übergabe (Arzt-Arzt). Core principle: **SPRACHKOMPETENZ im klinischen Alltag**, NOT medical knowledge.

## FSP-Prüfungsstruktur (3 Teile, je 20 min)
1. **Teil 1: Arzt-Patienten-Gespräch (Anamnese)** – laienverständliche Sprache, Empathie, Zeitdruck. Fachsprache zum Patienten = FEHLER.
2. **Teil 2: Dokumentation** – Kurzdoku (Halbsätze, schnell) + Aufnahmebericht (ganze Sätze, ausführlich). Verdachtsdiagnose IN Fachsprache.
3. **Teil 3: Arzt-Arzt-Gespräch (Übergabe)** – Fachsprache GEFORDERT. Strukturierte Fallvorstellung. Medizinische Fehler werden NICHT bewertet, nur Sprachkompetenz.

## Tech Stack
- Next.js 14 (App Router) + TypeScript
- Supabase Auth (NOT NextAuth)
- Prisma + PostgreSQL (Abacus-hosted)
- Mistral AI (`mistral-large-latest`) for LLM tasks
- i18n via `react-i18next`, supported langs: de/tr/en
- Tailwind CSS + shadcn/ui + framer-motion

## Key Patterns
- **i18n usage**: `const { t, i18n } = useTranslation(); const lang = i18n?.language ?? 'de';`
- **Route structure**: `/dashboard`, `/simulation/new`, `/simulation/[templateId]/briefing`, `/simulation/[templateId]/chat`, `/evaluation/[simId]`, `/coaching`, `/glossary`
- **DB connection rules**: ephemeral connections, max 25 concurrent. Reuse the singleton `prisma` client.
- **Force dynamic** in any route reading `process.env.NEXTAUTH_URL` or doing live DB.

## Schema (key models)
- `Profile` — user profile linked to Supabase auth (uuid pk = supabase user id)
- `SimulationTemplate` — has `checklist` (JSON: `{id, textDe, textTr, weight 1-3, category}`)
- `UserSimulation` — student attempt, has `documentation`, `languageMode` (`german_only`, `bilingual`, `bilingual_en`)
- `SimulationInteraction` — chat turns
- `Evaluation` — has `scores` (JSON), `checklistResults` (JSON, per-item: `{id, fulfilled, score 0-10, commentDe, commentTr}`), `docFeedback*`, `docScore`, **`coachingFeedbackDe/Tr`** (optional, opt-in detailed coaching)
- `FspProgress` — tracking progress entries
- `HandbookSection` — RAG knowledge base
- `GlossaryTerm` — DE-TR glossary

## Important Behavioral Rules
- User communicates in **German**. Direct, pragmatic, no fluff.
- LLM evaluation runs automatically after a simulation (`/api/simulation/evaluate`).
- **Coaching Feedback (`/api/simulation/coaching-feedback`)** is OPT-IN — user must click "Coaching-Feedback anfordern" button on evaluation page. Cached after first call, can be regenerated with `force: true`.
- **Weighted Score** is the primary metric in evaluation: `sum(score_i × weight_i) / sum(weight_i × 10) × 100`. Display as % in the overall card.
- **Checklist preview in briefing** is OPT-IN (Eye/EyeOff button, default hidden) — for studying.
- Three-language switcher in header (DE / TR / EN).
- Support language in briefing: 3 options (None / TR / EN), maps to `languageMode`.
